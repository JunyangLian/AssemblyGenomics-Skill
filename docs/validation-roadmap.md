# 验证路线图：三层验证体系（D-026 决策系统的验证集）

> 2026-09-24 制定。目的：把 D-026 的"可靠性决策系统"从叙事变成**可度量的系统**——
> 判定（继续/警告/回退/补检查）必须在三个层级上被独立验证，而不是靠会话内经验断言。

## 三层结构

| 层 | 名称 | 数量 | 验证什么 | 成本 | 顺序 |
|---|---|---|---|---|---|
| T3 | 规模化规则验证 | 几十~上百 | 判定规则的**输入**：异常检测的特异性（正常数据不误报）与敏感性（已知异常能触发） | 低（GFF/统计解析，免算力） | **先做**（杠杆最高） |
| T2 | 阶段级真实案例 | 8-10 | 判定的**输出**：给真实阶段产物，判定 继续/警告/回退/补检查 是否与预标注一致 | 中（复用手头资产，免算力） | 并行 |
| T1 | 核心端到端案例 | 3-5 | 判定的**端到端集成**：识别数据→路由→SOP→执行→checkpoint→诊断→最终结果 | 高（1-3 天算力/案例） | 随算力推进 |

## T3 规模化规则验证（先做）

- **数据源**：NCBI 公开 GFF/组装统计（datasets API / FTP 批量，D-017 网络纪律），
  目标 30-100 个物种，覆盖已有基线类群 + 新类群
- **验证内容**：
  - 基线规则特异性：正常 RefSeq 注释在类群兜底带内不误报（advisory 带 → 群体实测分布）
  - 基线规则敏感性：构造/已知异常（基因数虚高、缺 CDS、BUSCO 缺失异常）能触发
  - 陷阱检查器：PIT-005（非编码残留）、PIT-008 前置（header 规范性）批量跑
- **产出**：`knowledge/baselines/` 类群带从 case_reference 升级为 **population-validated**
  （D-016 enforce 档愿景落地）；判定准确率/误报率首份统计
- **前置改造**：check_baselines / run_pitfall_checks 支持批量调用（目录输入、逐案例判定表输出）

## T2 阶段级真实案例（并行）

- **数据源**：手头真实项目的阶段产物（葡萄注释全套、Siganus 三套组装各阶段、
  Qatar 功能注释、FCS-GX/BUSCO 结果等）
- **测试模式**：阶段回放——给 skill 真实产物，判定 继续/警告/回退/补检查
- **关键要求**：每个用例必须**预标注预期判定**（领域判断先行，无预标注不评分）
- **注册表**：`docs/validation-cases/VC-*.yaml`（id/tier/input/expected_verdict/actual/status）
- **首批种子**：酵母环已发生的 4 个判定点（见下）

### T1 执行说明（2026-09-24 定）

- **T1 形态**：与酵母环一致——已发表参考组装 + 公共 RNA-seq（SRA）→ 结构注释 → 功能注释。
  从 raw reads 的 de novo 组装端到端另列（葡萄 #001，算力大，单独立项）。
- **lineage 盘点**（服务器 /home/user/busco_downloads/lineages/ 实测）：
  actinopterygii_odb10/odb12 ✓（鱼类零下载）、eudicotyledons_odb12.2 ✓ / embryophyta_odb12.2 ✓
  （拟南芥零下载）；diptera ✗ 需下载（busco-data.s3.amazonaws.com 服务器实测可达，1.4MB/s）。

- **成本预估**（相对酵母 4h）：拟南芥 135Mb ≈ 1-2 天；果蝇 140Mb ≈ 1-2 天；青鳉/河鲀 400-700Mb ≈ 2-4 天。
